Read environment variables from the running OpenCode process — cross-platform without launching a shell.

Actions:
- `get`: return the value of a single variable. Required: `name`. Returns `value` (string) or `null` if not set.
- `has`: return whether a variable is set. Required: `name`. Returns boolean only — never the value, so it is safe to call on secret-looking names.
- `list`: enumerate all variable names. Optional: `name_pattern` (case-insensitive substring) to filter. Optional: `include_values` (default false). Optional: `mask_secrets` (default true) which replaces any value where the name looks secret-ish (contains key/secret/token/password/auth) with `***`. Optional: `limit` (default 200, max 1000) caps the result.
- `match`: return all variables whose names match a regex (`pattern`, JS flavour). Same `include_values` / `mask_secrets` controls.

Why this exists:
- On Windows the equivalent of `echo $VAR` is `echo %VAR%`, which differs in cmd vs PowerShell, and bash via Bun runs through MSYS quoting rules. This tool sidesteps all of that.
- It avoids spawning a child process for every lookup.
- It avoids the agent accidentally pasting a real secret into chat: the default for `list` and `match` is metadata-only (names + masked values).

Limits:
- This tool only reads — it cannot mutate the environment of the OpenCode process. To set an env var for a child, prepend `KEY=value` in the bash tool call.
- `name` is limited to 256 characters and matches `[A-Za-z_][A-Za-z0-9_]*` style names plus lowercase variants for compatibility.
- `pattern` is limited to 1024 characters.
- `limit` is clamped to [1, 1000].
- The "secret-ish" detection is a heuristic, not a guarantee. Treat any value pulled with `include_values: true` as sensitive.

Examples:
- `{ "action": "get", "name": "PATH" }`
- `{ "action": "has", "name": "OPENAI_API_KEY" }`
- `{ "action": "list", "name_pattern": "OPENCODE", "include_values": true, "mask_secrets": true }`
- `{ "action": "match", "pattern": "^(HTTP|HTTPS|NO)_PROXY$", "include_values": true }`
